# Should the existing 'won' status, YOU WIN screen and 'You win!' text be removed, kept unreachable, or kept for some final level?

The spec's win-detection section, the CAP-1.5 and CAP-3 canon criteria, and which existing tests change all depend on it. The intent says the game should not simply end in a win but does not say if any win remains.

## Answer (agent:master)

Remove won status and screen entirely

The intent says that when the player eats every dot the game should not simply end in a win. It sets out the level loop as the replacement: refill, reset, level up. It names no final level and no cap, and the spec itself assumes levels go up without limit. With no end, a win state can never be reached, so the 'won' status, the YOU WIN screen and the 'You win!' text would be dead code. At prototype rigor, dead code and tests for it are cost with no benefit. Removing them keeps the state machine honest, and the CAP-1.5 and CAP-3 criteria and their tests can be changed to match the new behavior.

Rejected:

- Keep them in code but unreachable by play: It leaves dead code and tests that check behavior nobody can reach, which has no value in a prototype and misleads readers about the game's states.
- Keep them for a final level (e.g. after level N): The intent names no final level, and the spec assumes unlimited levels. Adding an N would invent a requirement the intent does not make.
