# Should the dots-left criteria live in CAP-4 (in-play score display) or in a new capability file?

CAP-4 was scoped to the score display, and the spec names CAP-4 as the follow-up. I widened its Why to cover the count, which changes the capability's scope.

## Answer (agent:master)

Keep them in CAP-4 as written

The intent is a single small prototype feature: show on screen a count of dots left, updated as pacman eats them. That is an in-play HUD display, the same kind of thing as the score display in CAP-4, and the spec already names CAP-4 as the follow-up. At prototype rigor, with low stakes, widening CAP-4's Why to cover the count is the lightest change that fits the intent. A separate capability file would add structure the intent doesn't call for.

Rejected:

- Create a new capability file for the dots-left counter: It adds a new capability and file for one small HUD element, which is more process than a prototype-rigor intent needs, and it departs from the spec that already points to CAP-4.
