# Who writes the Playwright tests for CAP-4.1, CAP-4.2 and CAP-4.3 in tests/e2e/app.spec.ts, given that the dev seat owns only src/**?

The dev plan puts the DOM text and bounding-box checks in Playwright, but that file is outside the dev seat's OWNS and playwright test is not an allowed command. Until someone writes and runs them, P0-UI-009, -010 and -011 rest only on unit-level stand-ins and E2's Playwright half is unverified.

## Answer (agent:master)

Accept the unit-level stand-ins at prototype rigor

The intent is small: show the existing score next to the lives during play, with no change to scoring. The rigor is prototype and the stakes are 0.2. At that level, unit-level checks of the score value and its updates are enough evidence. Playwright checks of DOM text and bounding boxes are a higher bar than the intent asks for. Widening dev's OWNS would not close the gap by itself, because playwright test is also not an allowed command for dev, so the tests could be written but not run. The E2 Playwright half should be recorded as unverified at prototype rigor, not treated as a blocker. Nothing else in the plan needs to change.

Rejected:

- Add tests/e2e/app.spec.ts to dev OWNS for this wave: It widens dev's ownership and still leaves the tests unrunnable, since playwright test is not an allowed command. It adds scope that a prototype-rigor display change does not need.
- Another seat writes the e2e tests: It adds a cross-seat handoff and extra work for a 0.2-stakes cosmetic feature. Prototype rigor does not require browser-level layout verification.
